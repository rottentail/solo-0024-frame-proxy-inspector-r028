# 两阶段代理分镜检查：设计评估

状态：设计交付（本轮不实现流水线代码）
证据：`tools/check_proxy_probes.py`（可用 `PYTHONPATH=src:. python3 tools/check_proxy_probes.py` 独立复算本文全部实测数字）

## 0. 结论摘要

1. 两阶段处理**可以**承诺：在"代理统计与原片统计一致"的素材上，用约 `N/16 + K·w` 的整帧等价读取（N=帧数，K=候选数，w=确认窗口）得到与从头精查**完全相同**的已证实切点集合；实测友好素材上为全扫描成本的 17.8%（P5，3000 帧）到 59.2%（P1，17 帧演示片）。
2. 两阶段处理**不能**承诺：代理不可见的切点被找回。实测存在全分辨率可切（距离 0.2812 ≥ 阈值 0.215）而代理距离仅 0.0110 的素材，把灵敏度提到允许上限 0.95 也不够（需要 1.63，超出 [0.05, 0.95] 域）——丢失的空间细节不能靠提高灵敏度补回来（P3a）。
3. 因此最终记录必须分级：**已由原片证实的切点/区间**与**仍需复核的代理-only 区间**分开持久化；代理帧号永远不得进入 `cut_frames`、`scenes` 或联系表 `tile_map`。
4. 等预算对比下，局部回看与从头精查的漏检风险形状不同：前者是素材依赖的（代理不可见切点），后者是结构性的（预算耗尽后的尾部完全未检）。两者都不能宣称普遍替代对方；两阶段的优势是它**知道并报告**自己没证实什么，而从头精查的未知是隐式的。
5. 预算不足必须是一等结果：候选未清完或代理-only 区间超上限时，检查以 `indexed_partial`（显式覆盖清单）或 `INSPECTION_BUDGET_EXHAUSTED` 失败码收场，不得静默产出"看似完整"的结果。

## 1. 现状基线与成本模型

### 1.1 生产代码事实（设计的约束条件）

- 指纹（`src/frame_proxy/media/fingerprint.py`）：16 桶亮度直方图 + 均值 RGB + 对比度，距离权重 0.55/0.35/0.10。**纯全局统计，不含任何空间布局**；且每帧内部已做跨行抽样（`step = max(1, pixel_count // 8192)`，1920×1080 时 step=253）——现行"原片精查"的指纹本身就是一种抽样统计。
- 检测器（`src/frame_proxy/media/detector.py`）：阈值 `0.50 − 0.30·sensitivity`（s=0.55 → 0.335，s=0.95 → 0.215）；贪心切点 + `min_scene_frames` 双侧守卫（距上一切点和距片尾都要够）。
- 检查流程（`src/frame_proxy/service/inspections.py:56-69`）：整文件读入内存、SHA-256 校验后，对 `range(0, N, sample_stride)` 逐帧全分辨率解码。`sample_stride` 允许 1–4（`src/frame_proxy/domain/policies.py:100`）——**时间抽帧是已上线的"代理"**。
- 联系表（`src/frame_proxy/service/contact_sheets.py:71-84`）：只按 inspection 记录的原帧号用 `decode_frame_at` 解码原帧；`tile_map[].source_frame` 即原帧号。这一行为必须保留。
- 服务上限（`src/frame_proxy/config.py`）：3000 帧、64 MB、1920×1080。

### 1.2 成本模型

预算单位 = **整帧等价解码**（一帧完整 BGR→RGB 解码 + 指纹）。固定成本（整文件读入 + SHA-256 完整性校验）两种策略都要付，不计入对比。空间跨 k 子解码触及 1/k² 像素字节，记成本 1/k²。

### 1.3 代理的三种定义与取舍

| 代理 | 读取成本 | 统计保真 | 结论 |
| --- | --- | --- | --- |
| 空间跨行子解码（最近邻，stride k） | 1/k² | 对非周期内容是全局统计的无偏子样本；周期细纹会混叠（P3） | **采用**，k=4 为默认 |
| 盒式平均降采样 | 1（必须读全部源像素） | 扭曲统计本身：实测对比度 8.00→0.00、直方图 {7:.5, 8:.5}→{8:1.0}（P3c），阈值不可迁移 | 排除：不省读取且改变被测对象 |
| 时间抽帧（现行 sample_stride） | 1/k | 空间全保真；短于 k 帧的镜头不可见（P4） | 保留为独立旋钮；triage 阶段时间 stride 固定为 1 |

## 2. 两阶段能承诺什么

### 2.1 承诺分级（记录必须照此分层）

- **Tier-0 已证实切点**：切点两侧相邻**原帧**的指纹距离 ≥ 阈值，由生产 `analyze_frames` 代码路径在原帧号上算出。可独立复算：任何人用同一原片、同一参数重跑必得同一切点。
- **Tier-1 已证实区间**：区间内部做过原帧稠密扫描（stride 1 或检查声明的 stride），区间内无漏检由扫描本身保证。
- **Tier-2 代理-only 区间**：只有代理证据。代理"干净"**不等于**已证实干净（P3a 反例），必须作为待复核范围显式持久化。

### 2.2 帧号身份规则

1. `cut_frames`、`scenes[].start_frame/end_frame/representative_frame`、联系表 `tile_map[].source_frame` 永远是原帧号，可被 `decode_frame_at` 直接解码验证。
2. 代理帧号只允许出现在记录的 `triage` 诊断块中，并必须带映射参数（`proxy_stride`、`proxy_phase`），命名显式（如 `proxy_candidate_frames`），不得与上述字段混用。映射方向唯一：`original = proxy_index × stride + phase`，在 triage 结束时即转换，之后代理编号销毁。
3. 联系表瓦片永远从原片按原帧号解码（现行行为）；瓦片的 `provenance` 标签反映其场景的覆盖等级，与代理无关。

### 2.3 明确不能承诺的

- 检测器固有盲区不因两阶段改变：实测左右半屏互换的两场景，逐像素平均差 106.7/255，而全分辨率与代理的指纹距离都是 0.0000（P2）。这不是代理造成的，两阶段既不背锅也不居功。
- 渐变/溶解：现行检测器是硬切检测，两阶段同样不覆盖。
- 代理不可见切点（P3a 类）：无法承诺找回，只能承诺**不谎报**——未证实的范围显式标注。

## 3. 实验证据（可独立复算）

全部探针只调用生产代码路径（`probe_avi` / `decode_frame_at` / `fingerprint_frame` / `fingerprint_distance` / `analyze_frames`），对抗性素材由探针脚本内嵌的确定性 AVI 构造器生成。

### P1 友好素材：代理与原片结论一致

演示片（128×72，4 场景 17 帧，生产 `build_sample_avi`）：

| 分辨率 | 场景内最大距离 | 切点距离（帧 5/9/14） | 切点集合 |
| --- | --- | --- | --- |
| 全分辨率 | 0.0001 | 0.6123 / 0.7198 / 0.6741 | [5, 9, 14] |
| 代理 stride-2 | 0.0005 | 0.6123 / 0.7198 / 0.6741 | [5, 9, 14] |
| 代理 stride-4 | 0.0020 | 0.6135 / 0.7198 / 0.6741 | [5, 9, 14] |

阈值 0.335，切点距离余量约 2 倍。成本：全扫描 17.0；两阶段 17/16 + 9 确认帧 = 10.06（59.2%）。

### P2 调色板碰撞：与代理无关的盲区

半屏红/半屏蓝互换：全分辨率距离 0.0000，代理距离 0.0000，任何灵敏度下两者都不切。**该漏检不是代理引入的。**

### P3 混叠：代理的失败模式（量化）

- **P3a 漏检**：棋盘格 (136,120) → 纯灰 128。全分辨率距离 0.2812 ≥ 0.215（s=0.95 可切）；代理 stride-2 距离 0.0110。让代理抓到它需要灵敏度 1.63，超出允许上限 0.95——**灵敏度补不回空间细节**。
- **P3b 幻觉**：棋盘格 (120,136) 与其相位反转。全分辨率距离 0.0000（任何灵敏度都不切）；代理距离 0.5720（产生假候选）。确认环节用原帧证据拒绝它——**假候选消耗预算但不进入记录**。
- **P3c 盒式代理失真**：对比度 8.00→0.00，直方图双桶塌成单桶——盒式平均改变被测统计量本身，故排除（见 1.3）。

### P4 时间抽帧：短镜头消失与切点错位

2 帧镜头位于 [6,8)：stride-1 切点 [6, 8]；stride-4 切点 [8]——镜头整体不可见，且边界从 6 错位到 8。**代理帧号直接当原帧号就会产出这种错误身份。**

### P5 等预算对比（确定性模拟，参数见脚本）

N=3000（服务帧数上限），39 个切点均布，30 个代理假候选（P3b 类素材），代理成本 1/16，确认窗口 w=5（候选 ±2 原帧）：

| 预算 B | A 已证实 | A 未检查 || B 已证实 | B 假候选过滤 | B 未决候选 | B 成本 |
| --- | --- | --- | --- | --- | --- | --- |
| 300 | 3 | 36 || 12 | 10 | 47 | 297.5 |
| 600 | 7 | 32 || **39（全部）** | 30 | 0 | 532.5 |
| 1200 | 15 | 24 || 39 | 30 | 0 | 532.5 |
| 3000 | 39 | 0 || 39 | 30 | 0 | 532.5 |

对抗场景（3 个代理不可见切点，位置 750/1500/2250）：B=600 时 B 证实 36 个，3 个必须报告为未复核。

## 4. 等预算对比：局部回看 vs 从头精查

### 4.1 成本代数

- A（从头精查）：成本 = min(B, N)；证实切点 = 位置 < B 的切点。
- B（两阶段）：成本 = N/16 + (K − M + F)·w，其中 K=真实切点，M=代理不可见切点，F=假候选。预算不足时按文件顺序确认，未决候选显式入册。

### 4.2 误切传播

- A 的误切 = 检测器在原帧上的固有误报（场景内噪声越阈），直接进入记录。
- B 的代理假候选（P3b 实测 0.5720 vs 原片 0.0000）经强制确认过滤，**不进入记录**；代价是预算（P5 中 30×5=150 整帧当量 = N 的 5%）。间接风险：假候选挤占预算会饿死后续真候选——故确认顺序按文件顺序（无偏），且未决候选必须入册，不得静默丢弃。
- 结论：最终记录的误切率 B ≤ A；B 的额外成本是确认开销。

### 4.3 漏检风险

- A：结构性漏检。预算耗尽处之后的尾部**完全无信号**，均布切点下期望漏检 K·max(0, 1−B/N)（P5：B=600 时漏 32/39）。
- B：素材依赖性漏检。代理不可见切点（P3a 类）在任何预算下都漏；其余全部证实。友好素材 M=0（P1），对抗素材 M 不可先验 bound。
- 关键不对称：B 的未知集合是**显式的**（未决候选 + 代理-only 区间入册），A 的未知集合是隐式的（尾部看似"没切点"，实则"没看"）。

### 4.4 结论

- 当 `N/16 + (K − M + F)·w ≤ B < N` 且素材使 M 可接受时，B 严格优于 A（P5：B=600，B 证实 39 vs A 证实 7）。
- 当 B ≥ N 时两者等价，B 仍省 82% 读取（532.5 vs 3000）。
- 当素材对抗（M 大或 F 大）时，B 必须把未证实范围入册或承认预算不足；A 同样漏（尾部），只是不说。**任何一方都不得宣称普遍替代原片全扫描。**

## 5. 素材分类与适用性矩阵

| 素材类 | 证据 | 两阶段行为 |
| --- | --- | --- |
| 平坦/图形内容、全局调色差异、切点距离 ≫ 阈值 | P1：代理与全分辨率切点集合相同，距离差 ≤0.0012 | **可减少读取而不改变已证实结果**；triage 后少量确认即完整 |
| 周期细纹、胶片颗粒、高频频谱内容 | P3a/P3b：代理漏检与幻觉都实测存在 | triage 只能当提示；不确定带内邻接对必须原帧确认；已知此类素材应直接加宽确认窗口或回退稠密扫描 |
| 短镜头密集（镜头长 < 时间 stride） | P4：2 帧镜头在 stride-4 下消失且切点错位 | triage 时间 stride 固定为 1；不接受时间维省读 |
| 同调色场景（对话正反打、同场景不同构图） | P2：全分辨率同样漏 | 两阶段不改变结果；不得把此类漏检记到代理头上，也不得宣称解决 |
| 切点距离贴近阈值的噪声素材 | 阈值公式 + P1 场景内噪声随 stride 上升（0.0001→0.0020） | 不确定带 [τ−ε, τ+ε] 内全部转确认；ε 由 P3 类构造标定（建议初值 0.05） |

**能减少读取而不改变已证实结果的判据（可在线检查）**：代理距离落在确定带之外（≥τ+ε 或 ≤τ−ε）的邻接对占绝对多数，且确认结果与代理候选一致。P1 类素材满足；P3 类素材会在确认环节暴露分歧，此时分歧本身就是"必须回退原帧"的信号。

**必须承认预算不足的情形**：不确定带内邻接对比例过高（确认预算将超过稠密扫描）、未决候选在预算耗尽时仍非空、或代理-only 区间占比超配置上限（建议 0.2）。此时以 `indexed_partial` + 显式覆盖清单收场，或直接 `INSPECTION_BUDGET_EXHAUSTED` 失败——承认不足是一等结果，不是异常。

## 6. 记录与流程设计（供实施轮次）

### 6.1 InspectionRecord 扩展（仅设计）

```json
"coverage": {
  "complete": false,
  "proven_ranges": [[0, 512]],
  "proxy_only_ranges": [[512, 3000]],
  "confirmed_cut_frames": [75, 150],
  "unresolved_candidates": [2250],
  "triage": {
    "proxy_stride": 4,
    "proxy_phase": 0,
    "proxy_candidate_frames": [18, 37],
    "note": "proxy indices are diagnostics only; original = index*stride+phase"
  }
}
```

### 6.2 状态机

`scanning -> indexed` 仅当 `coverage.complete == true`；新增终态 `indexed_partial`（预算耗尽但部分结果可用，携带完整 coverage 清单）；`INSPECTION_BUDGET_EXHAUSTED` 走既有 `failed` 通道，稳定错误码入 `error_code`。

### 6.3 联系表门控

- 默认仅接受 `indexed`（完整）检查，行为与现行完全一致。
- 对 `indexed_partial` 需在请求中显式 `allow_unreviewed: true`；产出的 `tile_map` 每格增加 `provenance: "proven" | "unreviewed"`；未复核场景的代表帧 = 映射后的**原帧号**，瓦片仍从原片解码。
- 任何字段都不得出现代理帧号（§2.2 规则 2）。

## 8. 非承诺（防止误用）

1. 不以 P1 类成功样本宣称代理可普遍替代原片——P3 已实测反例存在。
2. 代理证据永远不进入最终记录的已证实部分；它只分配确认预算。
3. 不修复检测器固有盲区（P2），不覆盖渐变/溶解。
4. 固定成本（整文件读入 + SHA-256）两种策略同付；若未来它成为主导成本，代理的相对收益要重新评估。
5. 服务上限（3000 帧/64 MB）下全扫描最坏 3000 整帧当量，两阶段的绝对收益有界；其核心价值是**预算约束下的显式覆盖分级**，而非无限扩展检查规模。
